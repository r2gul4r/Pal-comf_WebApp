# 회고

## 잘 된 점

가장 잘한 결정은 UI부터 만들지 않고 설치본 데이터 한 묶음을 먼저 끝낸
것이다. 팰 이름, 작업 적성, 파트너 파라미터, 패시브 정의, 한국어 설명과
아이콘이 서로 다른 자산에 흩어져 있었다. 샘플 5종을 먼저 묶지 않았다면
겉보기에는 그럴듯하지만 버전과 효과 범위가 틀린 화면을 만들 가능성이 컸다.

게임 데이터와 표시 문구를 둘 다 보존한 것도 유효했다. 핑토 외부 페이지는
본문에서 “다른 거점 팰의 적성 레벨 +1”이라고 하면서 표에서는 “모든 팰
+1%”로 표시했다. 설치본의 `ToBaseCampPal`, `bNotAssignSelf=true`,
`WorkSuitabilityAddRank_Handcraft`와 한국어 원문을 같이 확인했기 때문에
범위와 단위를 안정적으로 결정할 수 있었다.

추출기와 웹앱을 분리한 덕분에 웹앱은 40GB pak이나 로컬 설치 경로를 알
필요가 없다. 게임 업데이트 뒤에는 추출만 다시 실행하고 UI와 검색 테스트는
그대로 유지할 수 있다.

## AI가 틀렸거나 성급했던 부분

AI는 CUE4Parse API를 기억에 의존해 몇 번 잘못 추정했다. `Name.Text`,
컬렉션 `Count`, 텍스처 디코딩 반환형 가정이 모두 컴파일에서 깨졌다.
고정한 NuGet 버전의 실제 소스와 컴파일러 오류를 기준으로 바꾸고 나서야
아이콘 추출이 안정화됐다.

전체 정규화 첫 구현은 파트너 파라미터의 대상 팰과 발동 조건 팰을 합쳤다.
플루미 효과에 흘루미가 적용 대상으로 보이는 오류였다. 한국어 문장과
`TargetType=ToSelf`를 다시 비교해 `PalTribeIds`를 발동 조건으로 분리했다.

설명 렌더러도 패시브 자리표시자만 처리해 플로리나의
`{ActiveSkillMainValueByRank}`를 남겼다. 생성 JSON의 모든 표시 설명에서
남은 `{...}`와 마크업을 검색하는 검사를 추가해 발견하고 수정했다.

웹 쪽에서는 최신 버전을 그대로 고르는 것이 항상 정답이 아니었다.
TypeScript 7은 당시 `typescript-eslint` 지원 범위를 벗어났다. 지원되는
최신 6.0.3으로 내렸고, React 최신 린트가 지적한 불필요한 수동 memoization도
제거했다.

## 안전 측면에서 아쉬운 점

실제 게임 UI와 대조하려고 게임을 실행한 것은 계획이 부족했다. 실행 전에
세이브 파일 해시 기준선을 남기지 않았고 사용자 입력과 자동화 입력이 겹쳐
기존 월드가 열린 상태가 됐다. 핵심 `.sav` 수정은 관측되지 않았지만
`steam_autocloud.vdf`는 갱신됐다.

이후 게임 UI 자동화를 중단하고 설치본 pak 읽기와 외부 페이지 교차검증으로
전환했다. 다시 한다면 게임 실행 전에 세이브 디렉터리의 파일 목록, 해시와
수정 시각을 먼저 기록하거나, 아예 사용자가 직접 제공한 스크린샷만
대조할 것이다.

## 다음 개선

현재 MVP는 작업 적성 증가와 작업 속도 증가에 집중한다. 다음 버전에서는
농작물 성장 속도, 수확량, 포만도와 SAN처럼 거점 생산성에 간접 영향을 주는
효과를 별도 카테고리로 확장할 수 있다. 작업 적성과 섞으면 검색 의미가
흐려지므로 같은 필터에 억지로 넣지는 않는다.

게임 Build ID가 바뀔 때 매핑 호환성과 스키마 변화를 자동 비교하는 회귀
리포트도 필요하다. 현재는 생성 실패로 변경을 감지하지만, 어떤 행과 필드가
바뀌었는지 보여주는 diff가 있으면 유지보수가 더 빨라진다.

마지막으로 자동 데모는 동작 증명용 무음 영상이다. 검색 결과와 지도 상세가
한 화면에 다 들어오지 않는 구간은 중앙 스크롤과 장면 분리로 보완했고 단계별
한국어 자막을 넣었다. 처음 만든 69초 영상은 구현 세부가 너무 많았고, 최종본은
목장 관련 팰 검색·장인 기질 검색·불길한 알 좌표 확인만 남겨 32초로 줄였다.
