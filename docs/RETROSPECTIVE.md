# 회고

## 이번 작업에서 가장 잘됐다고 느낀 점

이번 작업에서 가장 잘됐다고 느낀 점은 내가 불편했던 점을 확실하게
해결했다는 것이다.

팰월드 정식 버전에 새로운 패시브와 스킬이 생겼지만 인게임에는 검색
기능이 없었다. 인터넷에 있는 DB도 팰을 하나씩 확인해야 필요한 정보를
알 수 있었다. 그래서 작업이나 패시브 키워드 하나로 어떤 팰이 필요한지
바로 찾을 수 있는 검색기를 만들었다.

불길한 알 지도도 같이 하는 친구들은 알을 모두 찾았는데 나만 찾지 못해서
필요했던 기능이다. 게임 데이터에서 지도와 스폰 좌표를 읽고 한 화면에서
위치를 확인할 수 있게 만들었다.

## 어떤 도구를 어떤 순서로 활용했는지

1. Codex로 작업 범위와 게임 파일 안전 규칙을 먼저 정했다.
2. 현재 Steam 설치본의 manifest와 pak 인덱스를 확인했다.
3. `repak`, C#과 CUE4Parse로 필요한 게임 자산만 선택해서 읽었다.
4. 팰 5종 샘플로 이름, 작업 적성, 파트너 스킬, 패시브와 아이콘 연결을 먼저
   검증했다.
5. 전체 생성 데이터와 Antigravity 프론트를 결합했다.
6. 실제 화면을 보면서 검색 결과, 패시브 UI, 카드 크기와 지도 조작을
   반복해서 검수했다.
7. 테스트, 타입 검사, 린트와 빌드를 통과시킨 뒤 실행 영상을 만들었다.

## 막혔던 지점과 AI를 활용한 방법

중간중간 크게 막히는 부분은 없었다. 굳이 하나를 고르면 디자인 부분이었다.

패시브 UI는 일반, 노란색, 파란색과 세계수 디자인이 서로 달랐고 작업
아이콘도 처음에는 크기와 색이 인게임과 달랐다. 화면을 직접 확인하면서
이상한 부분을 구체적으로 지적하고, 게임 파일에 있는 UI 자산과 색상 분기를
다시 확인하게 했다. 세계수 패시브는 참고 이미지를 주고 원하는 보라색 효과의
정도를 직접 정했다.

## AI 결과를 검수한 방식

AI가 도출한 결과를 그냥 “아 그렇구나” 하고 적용하지 않았다. 왜 그렇게
했는지, 다른 더 좋은 방법은 없는지, 지금 방법이 제대로 된 건지를 계속
질문하고 검수하면서 작업했다.

## 결과가 틀리거나 마음에 들지 않았을 때

검색 결과에서 선택한 작업과 관계없는 팰이 나오는 문제를 발견했다. 한 건만
수정하지 않고 전체 효과와 필터를 다시 검수하도록 요청했다.
그 결과 효과가 적용되는 작업 범위를 구조화된 데이터로 분리하고 전체 검색
결과를 테스트하게 했다.

패시브 색상도 초절기교와 장인 기질이 기억한 색상과 다르게 표시되는 것을
확인했다. 이름별로 색을 임의 지정하지 않고 게임 파일의 Rank 분기와 실제 UI
자산을 전부 확인해 매칭하도록 했다.

디자인 결과가 마음에 들지 않을 때는 막연히 다시 만들라고 하지 않고,
패시브 UI 위치, 작업 아이콘 크기와 색, 카드 높이, 자막 문구처럼 바꿀 부분을
하나씩 지정했다. 수정된 화면과 영상을 로컬에서 먼저 확인한 뒤 다음 작업으로
넘어갔다.

## 다시 한다면

중간중간 막히는 부분이 크게 없었지만, 만약 더 복잡한 작업을 했을 땐 모든
막혔던 지점을 기록하고 시도했던 방법을 일단 기록하여 실패 아카이브를 만들고
다음 작업 때 비슷한 상황이 나왔을 때 참고할 수 있도록 할 것 같다.

AI가 틀리거나 이상하게 작업할 시 지침이 없다면 간단하게 지침을 세우고
정확하게 작업할 수 있도록 세세하게 설명하면서 차근차근 문제를 풀어간 뒤,
해결이라는 방향으로 성공적으로 흘러간 해당 흐름을 메모리에 저장할 수 있도록
문서화시켜서 다시 사용할 수 있도록 하는 방식을 사용할 것 같다.
